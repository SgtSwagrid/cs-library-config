## 👷 What's the workflow?

Changes made to the configuration files contained herein are automatically copied into each dependent project using [GitHub Graph](https://github.com/SgtSwagrid/github-graph).
Updates to these files should be made _here_, not in any of the downstream repositories, lest they be overwritten later.

## 📋 What's included?

Everything from [GitHub Config](https://github.com/SgtSwagrid/github-config), plus the following.

### Build

- Shared MSBuild settings in [`Directory.Build.props`](Directory.Build.props): the latest C# on .NET 10, nullable reference types, warnings as errors,
  and the NuGet package metadata common to every library (authorship, licence, [Source Link](https://github.com/dotnet/sourcelink), symbol packages).
- A build step in [`Directory.Build.targets`](Directory.Build.targets) which packs the README as each package's page on NuGet,
  converting its HTML header to Markdown, as nuget.org doesn't render HTML.
- A pinned .NET SDK in [`global.json`](global.json).

### Continuous integration

- Git settings including `.gitignore` and `.gitattributes`.
- Code style rules in [`.editorconfig`](.editorconfig), enforced by [`dotnet format`](https://learn.microsoft.com/dotnet/core/tools/dotnet-format),
  the standard [linter](https://en.wikipedia.org/wiki/Lint_(software)) of the .NET ecosystem, with automatic fixes on every PR.
- GitHub [Actions](https://github.com/features/actions) workflows to verify build integrity.
- [Dependabot](https://docs.github.com/en/code-security/dependabot) integration for automatic dependency updates.
- Configuration for [GitHub Rules](https://github.com/SgtSwagrid/github-rules) to define GitHub rulesets in-source.
- [Claude Code](https://claude.com/product/claude-code) integration with GitHub.

### Publishing

- GitHub workflows for publishing to [NuGet](https://www.nuget.org/) with [Trusted Publishing](https://learn.microsoft.com/nuget/nuget-org/trusted-publishing), whenever a GitHub release is created.
- API documentation generated by [DocFX](https://dotnet.github.io/docfx/) and published to [GitHub Pages](https://pages.github.com/) upon release.

### IDE configuration

- Some config for [Visual Studio Code](https://code.visualstudio.com/). [Rider](https://www.jetbrains.com/rider/) and [Visual Studio](https://visualstudio.microsoft.com/) read `.editorconfig` directly.
- An environment definition for GitHub [Codespaces](https://github.com/features/codespaces).

### Documentation

- Contribution guidelines in [`CONTRIBUTING.md`](CONTRIBUTING.md) and a [code style guide](docs/STYLE_GUIDE.md).

### Licensing

- The [MIT](https://tlo.mit.edu/understand-ip/exploring-mit-open-source-license-comprehensive-guide) licence,
  which I tend to use by default as it is fairly permissive.

## 🏗️ Where is this used?

The full list of projects that rely on this configuration is defined in [graph.json](.github/graph.json).

## 🤔 Should I use this in my projects too?

Only if you want to, but this exists mainly for my own convenience.
I would, however, argue that these settings are reasonable defaults for many modern C# libraries.

More likely, if you're starting a new project, you'll want to use the downstream template [C# Library Template](https://github.com/SgtSwagrid/cs-library-template).

## 🔨 How can this be used?

You have several options:

1. If you want continuous updates as this repository evolves, open a PR to add your project(s) to [graph.json](.github/graph.json).
   You'll also need to send me a [PAT](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens) with write access to the corresponding repositories.
2. If you want continuous updates, but want to deviate from my template according to your own needs, fork this repository and _then_ add your project(s) to [graph.json](.github/graph.json) (after removing the existing projects from the list). In this case, you can add the PAT yourself.
3. If you just want the settings without the updates, click '**Use this template**' on GitHub (for a new project), or simply copy and paste the files (for an existing project).

Note that [`Directory.Build.props`](Directory.Build.props) names me as the author of every package; you'll want to change that.
